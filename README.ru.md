# AIGeoLock

**Безопасный модульный шлюз для LLM с маршрутизацией через VPN-туннели с учётом географического расположения.**

AIGeoLock — открытый проект на Rust, цель которого — предоставить безопасный и расширяемый шлюз для доступа к большим языковым моделям (LLM) через контролируемые сетевые туннели.

Проект разрабатывается поэтапно с акцентом на модульную архитектуру, оригинальный код и проверяемые свойства безопасности.

> **Статус: ранняя стадия разработки — проектирование и начальная реализация ещё впереди.**
>
> AIGeoLock пока не готов к использованию в продуктивной среде.

## Цели проекта

- **Независимость ядра от провайдеров.** Поддержка разных LLM-провайдеров через отдельные модульные адаптеры.
- **Независимость сетевой архитектуры от протоколов.** Поддержка различных туннельных механизмов через чётко определённые интерфейсы.
- **Безопасность по принципу fail-closed.** Если требуемый защищённый маршрут недоступен, запрос должен блокироваться, а не незаметно переключаться на прямое соединение.
- **Маршрутизация с учётом географии.** Направление запросов через настроенные сетевые точки в соответствии с заданными политиками.
- **Windows как первая целевая платформа.** Начальная разработка ориентирована на Windows и Microsoft SSTP.
- **Поэтапная реализация.** Начинаем с одного LLM-провайдера и одного туннельного протокола, затем расширяем возможности без перестройки ядра.
- **Оригинальный код.** Реализация AIGeoLock разрабатывается самостоятельно на основе открытых стандартов и документации, с внимательным отбором сторонних зависимостей.

## Начальный охват

Для первой версии выбраны следующие направления интеграции:

- **Платформа:** Windows.
- **LLM-провайдер:** OpenRouter.
- **Туннельный протокол:** Microsoft Secure Socket Tunneling Protocol (SSTP).
- **Язык реализации:** Rust.

Это первоначальные цели разработки, а не уже реализованные или проверенные возможности.

## Архитектура

Планируемая архитектура разделяет следующие компоненты:

- **LLM Gateway** — принимает запросы клиентов и предоставляет единый API.
- **Адаптеры провайдеров** — преобразуют запросы и ответы между внутренней моделью шлюза и API конкретного провайдера.
- **Ядро маршрутизации** — применяет политики маршрутизации и управляет потоком запросов.
- **Туннельные модули** — устанавливают защищённые сетевые соединения и отслеживают их состояние.
- **Механизмы обеспечения безопасности** — гарантируют блокировку запросов, для которых невозможно обеспечить требуемый защищённый маршрут.

Ядро должно зависеть от стабильных внутренних интерфейсов, а не от конкретных провайдеров или реализаций туннельных протоколов.

## Принципы безопасности

Безопасность — обязательное требование к архитектуре, а не функция, которую можно добавить позднее.

- При недоступности защищённого маршрута работа должна прекращаться безопасным образом.
- Не допускается незаметное переключение на прямое соединение.
- API-ключи, учётные данные и чувствительные данные запросов не должны попадать в журналы.
- Сторонние зависимости необходимо проверять на совместимость лицензий, известные уязвимости и происхождение.
- Следует тестировать не только успешные сценарии, но и сбои, восстановление соединений и пограничные случаи.
- Ограничения платформы и требования к системным привилегиям должны быть документированы.

Фактические гарантии безопасности будут описываться и проверяться по мере реализации.

## Подход к разработке

AIGeoLock развивается итеративно с использованием ИИ в качестве помощника при разработке:

1. Формулируем небольшую, проверяемую задачу.
2. Реализуем минимально необходимое изменение.
3. Запускаем автоматические тесты и проводим ревью кода.
4. Обновляем документацию и фиксируем архитектурные решения.
5. Переходим к следующей задаче, когда текущая понятна и проверена.

Код, созданный с помощью ИИ, необходимо проверять и тестировать до принятия в проект.

## Лицензирование и сторонний код

AIGeoLock распространяется под лицензией Apache-2.0.

Проект стремится сохранять оригинальность собственной реализации. При необходимости допускается использование сторонних библиотек и инструментов при условии проверки совместимости лицензий, безопасности и соблюдения требований к указанию авторства.

## Текущий статус

Ближайшие задачи:

- определить архитектуру и модель угроз;
- сформировать основные интерфейсы ядра;

- разработать и протестировать механизм fail-closed.

На данном этапе проект не предоставляет гарантий безопасности для продуктивного использования.
